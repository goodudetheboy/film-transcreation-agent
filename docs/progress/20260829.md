# 2026-08-29

## Workspace layout pass: denser table + resizable split

Compared `FilmWorkspaceView` against a VoiceQ Pro screenshot the user provided
and identified the gaps (table density, character/speaker system, waveform
timeline, video pane proportion, real toolbar). Scoped this session to the
purely layout/CSS pieces the user confirmed: denser table + smaller default
video pane + a drag-to-resize divider between the panels. Explicitly deferred:
derived Start/End/Duration columns, character/speaker tagging, waveform
timeline, new icon toolbar — no backend/data-model changes this session.

- **`frontend/src/index.css`**: `.details-table` rows tightened (30px row
  height, smaller padding/font-size), vertical gridlines via `border-right`,
  and cells now truncate to a single line (`white-space: nowrap` +
  `text-overflow: ellipsis` + `max-width: 260px`) for a spreadsheet feel
  instead of wrapping. New `.details-table__cell--nowrap-exempt` opts the
  Source-badge and actions columns out of truncation. `.workspace__split`'s
  default ratio flipped from ~43/57 (table/video) to ~62/38 via
  `grid-template-columns: minmax(360px, 1.6fr) 6px minmax(360px, 1fr)`, with
  the middle `6px` track and new `.workspace__divider` rules (hover/dragging
  accent highlight) filling the space the old `gap` used to provide.
- **`frontend/src/components/DetailsTable.tsx`**: added `title` tooltips on
  the now-truncated text cells (Timestamp, Subtitle, builtin columns, custom
  columns) so the full value is still reachable on hover; row-click-to-edit
  and all `stopPropagation()` wiring left untouched.
- **`frontend/src/views/FilmWorkspaceView.tsx`**: new drag-to-resize divider
  between the table and video panels, modeled on `VideoScrubber.tsx`'s
  existing pointer-capture pattern (position-relative-to-container, not
  delta-from-drag-start). Split width persists to `localStorage`
  (`workspace.leftPanelWidth`, read/written inside try/catch for
  private-mode/storage-disabled safety) and is clamped to 360px minimums on
  each side. Below the existing 960px breakpoint the CSS media query still
  owns the stacked single-column layout untouched — the inline
  `gridTemplateColumns` override is only applied when `isDesktop` is true, so
  there's no specificity fight.
- **Two real bugs found only by live-driving the feature, not by
  `tsc`/tests** (no unit test covers this view):
  1. The mount `useLayoutEffect` that reads localStorage/measures the
     container ran with `[]` deps, but at that first render `film` is still
     `null` so the early-return path (`if (!film) return <p>Loading…</p>`)
     means `splitRef.current` is `null` too — the effect bailed immediately
     and, with an empty dep array, never got a second chance once `film`
     loaded and the real split `<div>` mounted. Result: the persisted/default
     width silently never applied after a reload (dragging still worked
     live, since those handlers read the ref at call time). Fixed by
     depending on `[film]` instead of `[]`, so the effect re-runs exactly
     when the workspace split mounts for real.
  2. The `ResizeObserver` callback reclamped `leftWidth` on every width
     change, including widths below the 960px breakpoint — while collapsed
     to the mobile stacked layout, the container is narrow enough that the
     clamp forces `leftWidth` down to the 360px minimum in the background
     (even though it isn't rendered there), silently overwriting the
     previously-dragged desktop value. Widening back past 960px then reused
     that poisoned 360px as its base and never recovered the real split.
     Fixed by skipping the `leftWidth` reclamp entirely when
     `width <= DESKTOP_BREAKPOINT`, only updating `isDesktop`.
- Live-verified in a real browser against the real dev backend (test mode):
  logged in, opened the existing "sex" film, confirmed the denser table with
  gridlines/truncation/tooltips, confirmed the video pane starts smaller by
  default, dragged the divider and confirmed both panels resize smoothly and
  respect the 360px minimums, reloaded and confirmed the dragged width
  persists (`localStorage` round-trip), shrank below 960px and confirmed the
  stacked layout with no divider, widened back and confirmed the split
  restores (post-fix — this is exactly where bug #2 was caught), and
  clicked a row into edit mode to confirm inputs/selects and Save/Cancel
  still work correctly in the denser cells.
- `tsc --noEmit` clean. Frontend suite: 49/49 passing (no `DetailsTable` or
  `FilmWorkspaceView` test file exists yet — this whole feature, including
  both bugs, was only exercised via live browser verification, not
  automated tests).

## Video playback fix, subtitle timeline blocks, table↔video sync, Project tab, resizable columns

Follow-up in the same session: the user pointed out the video preview was
black and asked for the bottom timeline to actually show subtitle
timing/blocks like the VoiceQ reference, plus moving Target Country/Create
Project to their own tab. Mid-turn, also asked for wider + individually
resizable Details-table columns.

- **Root cause of the black video**: `backend/src/routes/films.ts`'s mock
  branch of `POST /api/films/upload-video` discarded the uploaded buffer and
  returned a fabricated `gs://mock-bucket/{uuid}.ext` URL pointing at nothing
  — `toPlayableUrl()` turned that into a 404ing HTTPS URL. Fixed by writing
  the buffer to a new configurable `mockUploadsDir` (`.data/mock-uploads`,
  same `.data/` convention as `filmsDataFile`, already gitignored) and
  returning a real `http(s)://<host>/mock-uploads/<uuid>.ext?passcode=...`
  URL built from the request itself (`req.protocol`/`req.get('host')`). New
  `express.static` mount in `backend/src/app.ts`, placed *inside* the
  `guarded` router (after `passcodeMiddleware`) so it's protected like
  everything else — the passcode has to ride along as a query param since a
  plain `<video src>` GET can't carry a body, reusing the same
  `req.body?.passcode ?? req.query?.passcode` lookup the middleware itself
  uses. `toPlayableUrl()` needed no change — it already passes non-`gs://`
  URLs through untouched. New backend test in `filmsRoute.test.ts` (temp dir
  via `mkdtemp`, uploads a buffer, asserts the URL shape, then re-fetches it
  through the same `app` and checks `content-length` matches). Explicitly
  not fixed: the real (non-mock) upload path, and any film created *before*
  this fix — their fake URLs have no recoverable bytes.
- **`frontend/src/components/VideoScrubber.tsx`**: the per-entry render
  changed from a 2px tick at `startMs` to a `.scrubber__block` spanning
  `startMs`→`endMs` with a truncated text label, highlighted amber
  (`--warning`/`--warning-dim` tokens) while it's the active line. Blocks are
  `pointer-events: none` so all drag/click seeking still lands on the track
  itself, unchanged — no new interaction code needed. Scrubber height raised
  (24px→44px base, 32px→52px in the workspace override) to fit the label.
- **`frontend/src/components/DetailsTable.tsx`** — table↔video sync: new
  `currentTimeMs`/`onSeek` props; each row's `subtitleEntryId` is looked up
  against `film.subtitle.entries` to compute an active state
  (`.details-table__row--active`, same warning-amber treatment), and clicking
  a row now both seeks the video to that line's `startMs` *and* enters edit
  mode as before — both actions fire together, no conflict. Active row
  auto-scrolls into view (`scrollIntoView({block:'nearest'})`) via a
  `data-row-id` + container-ref effect.
- **`frontend/src/components/DetailsTable.tsx`** — wider, resizable columns:
  switched to `table-layout: fixed` with an explicit `<colgroup>`, wider
  defaults per column (e.g. Subtitle/Segment Description 260px vs. the old
  content-driven auto width), and a small `.details-table__col-resizer`
  drag-handle on each header's right edge using the same pointer-capture
  technique as the workspace-split divider, but delta-based (new width =
  width-at-drag-start + cursor delta) since a column's width isn't a
  position-on-a-track the way the pane split was. Widths are in-memory only,
  not persisted — a deliberate simplicity call. The old blanket
  `max-width: 260px` on `td` was removed (dead weight once `<colgroup>`
  governs actual width).
- **`frontend/src/views/FilmWorkspaceView.tsx`**: `Tab` widened to include
  `'project'`; the Target-country input + Create Project button moved out of
  the Details tab into a new Project tab (shows an empty-state placeholder
  when there are zero rows, matching the Progress tab's existing pattern) —
  a pure relocation, no behavior change, per the user's own framing ("I will
  fix that flow later").
- **Live-verified end-to-end in a real browser**, not just unit tests: since
  the existing "sex"/"testing" test films' video URLs are unrecoverable
  (created before this fix), generated a fresh small real `.mp4` with
  `ffmpeg` (a 6s `testsrc` pattern) plus a matching 3-line `.srt`, temporarily

## 23:40 — Decouple Details rows from the subtitle-entry FK (freeform start/end)

The user pointed out that locking every Details row to exactly one parsed subtitle
entry (ADR 0022) can't represent non-dialogue cultural-resonance issues — a visual
gag, a gesture, on-screen text — since there's no subtitle line to anchor to.
Recorded the reversal as a new ADR rather than silently deviating: added
[`0023-freeform-detail-row-timing.md`](../adr/0023-freeform-detail-row-timing.md)
and appended a forward-pointer note to `0022`'s Consequences (the film-creation
subtitle requirement in 0022 is unaffected — only the DetailRow FK and its
`<select>`-based UI are superseded).

- **Data model**: `DetailRow`/`DiscoveryResultRow` swap `subtitleEntryId` for their
  own `startMs`/`endMs` (`backend/src/services/filmTypes.ts`). Also dropped the
  single `timestamp` display string entirely — with independent start/end there's
  no one unambiguous "the" timestamp anymore, and it had no reader left once the
  table shows Start/End as their own columns. This retired `formatMsAsTimestamp`
  in `backend/src/services/timeFormat.ts` (every call site was a `timestamp:`
  computation being removed).
- **New `backend/src/services/subtitleOverlap.ts`**: `subtitleTextForRange()`
  overlap-joins the film's parsed subtitle entries against a `[startMs, endMs)`
  range — a range with no dialogue in it legitimately derives `''`, not an error.
  `routes/films.ts`'s POST/PATCH `/details` handlers now validate
  `endMs > startMs >= 0` instead of FK-checking against `film.subtitle.entries`,
  and compute `subtitleText` via this helper.
  - **Scope boundary, deliberately not touched**: the Gemini Discovery Agent's own
    prompt/schema (`discoveryAgent.ts`) still anchors every finding to a real
    subtitle entry id — only the tail of `runPass`, where the entry is already
    resolved, now emits that entry's `startMs`/`endMs` instead of its id. Teaching
    the agent itself to propose non-dialogue ranges is a follow-up, not built here.
- **`frontend/src/components/DetailsTable.tsx`**: the single "Timestamp" column
  (a `<select>` of subtitle entries in edit mode) is now two real, independently
  resizable columns, **Start** and **End**. Each is its own small text input in
  edit mode (`formatClock`/`parseClockToMs`, new `frontend/src/utils/timeFormat.ts`,
  mirroring the backend's old `formatMsAsTimestamp` shape), parsed on blur —
  reverting silently to the last valid value on unparseable input or an
  ordering violation (`endMs <= startMs`) — plus a "⏱ use current" button per
  field that grabs the live `currentTimeMs` playhead position. The Subtitle cell
  shows a live client-side preview (same overlap-join logic, small deliberate
  duplication of the ~4-line backend helper) while editing, before Save
  round-trips to the canonical server-computed value. `isRowActive`/row-click-seek
  now read `row.startMs`/`row.endMs` directly — no more subtitle-entry lookup.
  "+ Manually add details" is no longer gated on the film having subtitle entries;
  a new row defaults to `[currentTimeMs, currentTimeMs + 2s]`, clamped to the
  video's duration via a new `durationMs` prop threaded from `FilmWorkspaceView`.
- `AgentStatusPanel.tsx`'s pending-discovery-result caption now shows
  `formatClock(startMs) – formatClock(endMs)` instead of the dropped `timestamp`
  field. `VideoScrubber.tsx`/`SubtitleDisplay.tsx` were untouched — they render the
  film's actual subtitle timeline, a separate, still-valid concept from Details'
  own freeform rows.
- Mechanical `subtitleEntryId`→`startMs`/`endMs` rename across the existing test
  suites that cover this behavior, plus three new `filmsRoute.test.ts` cases:
  a range overlapping zero subtitle entries derives `subtitleText: ''`; a range
  spanning two adjacent entries derives their joined text; `endMs <= startMs`
  returns 400.
- **Live-verified in a real browser** against the real dev backend (test mode),
  same ffmpeg-generated-clip technique as the earlier session today: imported a
  fresh film with a 3-cue SRT (two adjacent cues 0–4s, a third at 6–7s, a
  deliberate silent gap 4–6s). Confirmed: the mock Discovery Agent's rows (one per
  subtitle entry) still display correctly in the new Start/End columns; a
  manually-added row over the silent gap (00:04–00:06) derived and persisted
  `subtitleText: ''`; editing that same row's range to 00:00–00:04 derived and
  persisted the joined `"Hello there. General Kenobi."`; the "use current" button
  correctly grabbed the live playhead position; typing unparseable text into the
  End field reverted silently to the last valid value; clicking a row seeks the
  video directly to `row.startMs` (verified via `video.currentTime`); active-row
  highlighting correctly follows `row.startMs`/`row.endMs`. Cleaned up: deleted the
  test film via a direct `DELETE` call, removed `frontend/public/tmp-test-assets/`
  and the local `backend/.data/mock-uploads/` scratch file.
- `tsc --noEmit` clean in both workspaces. Backend suite: 105/105 (3 new cases).
  Frontend suite: 54/54 (5 new, for the new `timeFormat.ts` utility).
  `test:integration` has one pre-existing, unrelated failure — a stale assertion
  in `films.integration.test.ts` still expects a `gs://` mock-upload URL, from
  before the earlier session today switched mock uploads to real `http(s)://`
  URLs (confirmed via `git stash` that the failure exists without any of this
  session's changes). Flagged as a separate background task rather than fixed
  inline, since it's unrelated to this change.
