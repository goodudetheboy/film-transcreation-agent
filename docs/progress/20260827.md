# 2026-08-27

## 00:15 — Real video upload path, file-backed film persistence, Analyze/Dialogflow removal

- **Films now support real video upload, not just a `gs://`/URL text field.** New
  `backend/src/services/videoBucketUploader.ts` — uploads either a fetched http(s)
  URL or an in-memory buffer (drag-and-drop / file picker) to a GCS bucket
  (`VIDEO_CLIPS_BUCKET`, default `silent-scholar-505618-u6-clips`), returning a
  `gs://` URI. Guards against SSRF (blocks loopback/private/link-local/metadata
  addresses before fetching a caller-supplied URL) and against non-video responses
  (rejects HTML from e.g. a YouTube watch-page URL) and oversized uploads
  (`MAX_VIDEO_UPLOAD_BYTES`, default 500MB, enforced both via `multer`'s limit and a
  streaming byte-count check). New `POST /api/films/upload-video` (multipart,
  `multer` memory storage) and `POST /api/films` now itself uploads a plain
  http(s) `videoUrl` to the bucket before creating the film (unless already
  `gs://`, or in mock/test mode). New deps: `@google-cloud/storage`, `multer`.
- Frontend `NewFilmView.tsx` gained a drag-and-drop file zone alongside the existing
  URL field (mutually exclusive — picking a file clears the URL and vice versa),
  with an "Uploading video to bucket…" status message while a real (non-test-mode)
  upload is in flight. Dropped the disabled "Script" field entirely — scripts are no
  longer collected at film-creation time (see the Discover Agent output paragraph
  below).
- **Films persist to disk now, not just in memory** — `docs/adr/0016`.
  `filmStore.ts` gained an optional `persistPath` (wired to `config.filmsDataFile`,
  default `backend/.data/films.json`, gitignored): every mutation rewrites the full
  film list to that file; on startup, an existing file's contents load verbatim and
  seed data is skipped (so a restart never resurrects a film the user deleted).
  Films also gained `preprocessing: { dialogue, gestures } | null` on the record
  itself, saved via a new `POST /api/films/:id/preprocessing` once the frontend has
  already run Discover Agent captioning — `FilmDetailView` now hydrates its
  timeline from the saved film on load instead of always starting empty. Films can
  now be deleted (`DELETE /api/films/:id`), with delete actions on both the list and
  detail views.
- New `backend/src/services/preprocessingToItems.ts` — once a film has real
  Discover Agent output, `POST /api/films/:id/create-project` now builds project
  items by chronologically interleaving dialogue + gesture entries (sorted by
  timecode) instead of falling back to the old mocked fixture details; the fixture
  fallback is kept only for a film that hasn't been through Discover Agent yet.
  Mirrored on the frontend as `utils/timeline.ts` (`buildTimeline`,
  `timecodeToSeconds`) feeding a new `TimelineList.tsx` component, and
  `utils/gsUrl.ts` (`toPlayableUrl`) to render a `gs://` video as a playable
  `<video>` src via its public HTTPS equivalent.
- **Removed the original Analyze tab and its Dialogflow CX pipeline entirely** —
  `docs/adr/0017`. It duplicated the same "flag lines for a target country" job the
  Films → Discover Agent → Project → Research pipeline now covers, and had no
  callers left. Deleted: `AnalyzeView.tsx`, `dialogflowClient.ts` /
  `mockDialogflowClient.ts` (+ their tests), `routes/analyze.ts` (+ its test and
  integration test), `@google-cloud/dialogflow-cx` dependency,
  `ResultsList.tsx`/`resultsStore.ts`, `ErrorBanner.tsx`. Dropped now-unused config
  keys `DIALOGFLOW_LOCATION`, `DIALOGFLOW_AGENT_ID`, `MAX_SCRIPT_LINES`,
  `REVEAL_DELAY_MS` from `Config`/`.env.example`. `test_agent.py` (the teammate's
  standalone Dialogflow CX reference script) is untouched, per CLAUDE.md's repo map
  — it was never part of the running app.
- Full suite verified before committing: backend 92/92, integration 4/4, `tsc
  --noEmit` clean in both workspaces. Frontend 64/72 — the 8 failures are the
  pre-existing `PasscodeGate.test.tsx` `localStorage`-undefined issue already noted
