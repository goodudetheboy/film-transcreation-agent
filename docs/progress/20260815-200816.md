## Decisions made (and where they're recorded)

- **Backend reality corrected mid-session**: earlier planning assumed Agent
  Engine `reasoningEngines.query`/`streamQuery`. The teammate's real
  `test_agent.py` uses **Dialogflow CX `detectIntent`** instead — a different,
  synchronous (non-streaming) API. Recorded in `docs/adr/0002` (marked as
  superseding the earlier assumption, not hiding it). Real deployment values now
  known: `PROJECT_ID=silent-scholar-505618-u6`, `LOCATION=us-central1`,
  `AGENT_ID=f475df77-4a24-4d7e-a6ff-a3f5d039f975` — in `proxy/.env.example`.
- **Proxy synthesizes the progressive SSE reveal** rather than getting real
  incremental streaming from Google, since `detectIntent` is one-shot. Recorded
  in `docs/adr/0006`, implemented as `revealDelayMs` in
  `proxy/src/routes/analyze.ts` (0 in tests, ~150ms in real use).
- **Integration-test mocking mechanism changed from the original plan**: `msw`
  can't intercept Dialogflow CX's Node client (gRPC-based, not HTTP/fetch).
  Switched to injecting a fake `DialogflowClient` via the same `createApp(deps)`
  seam used by proxy unit tests, while still driving a REAL HTTP server via the
  frontend's real `apiClient` — verified this satisfies the "never mock
  frontend→proxy" constraint by deliberately breaking the proxy and watching the
  integration test catch it.
- **`AgentEvent`/`FlaggedLine` types are duplicated, not literally shared** —
  one copy in `proxy/src/routes/analyze.ts` + `dialogflowClient.ts`, one in
  `frontend/src/api/apiClient.types.ts`, cross-referenced by comment. A real
  shared workspace package was considered and skipped for the "dead simple"
  scaffold — Vite/tsx don't transpile TS-source workspace packages out of the
  box without extra config, and it wasn't worth the setup cost yet.
- **`vitest` bumped from `^2.1.1` to `^4.1.10`** across all three workspaces —
  the root `vite@8.2.1` and vitest's originally-bundled `vite@5.4.21` were two
  separate copies, causing a `tsc` type conflict on the `test` config field in
  `vite.config.ts`. Bumping vitest deduped to a single `vite@8.2.1`, fixed the
  type error, and dropped npm audit from 5 vulnerabilities to 0 as a bonus.
