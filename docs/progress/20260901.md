# 2026-09-01

## 21:00 — Dark/light theme toggle

Added a light theme alongside the existing dark one. The app was already
fully CSS-variable driven (`frontend/src/index.css`), so this stayed a
bounded, frontend-only change:

- Added a light palette under `:root[data-theme='light']` in `index.css`,
  overriding surfaces/text/semantic colors and shadows. Removed the stale
  "dark app, no light variant" scrollbar comment and made the `.menu-bar`
  gradient theme-aware (was hardcoded to a dark color). Added `select`
  styling to `.field` (previously only textarea/text/password inputs were
  styled).
- New `frontend/src/utils/useTheme.ts` hook: reads/writes `localStorage`
  (`theme` key, default `dark`) and sets `data-theme` on
  `document.documentElement`.
- `HeaderSettings.tsx` gained a "Theme" select (Dark/Light) in the existing
  Settings modal, next to Test mode. `App.tsx` wires `useTheme()` through.
- Tests: `useTheme.test.ts` (new) and `HeaderSettings.test.tsx` (extended).

Decisions:
- No "system preference" auto-detection — explicit toggle only, persisted
  per-browser. Can revisit if requested.
- No ADR needed — this doesn't touch the pipeline architecture, just UI
  theming.
