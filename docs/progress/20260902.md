## 23:20 — De-modalize "Import new film" + richer prep animations

The "Import new film" screen (`ImportFilmModal.tsx`) was already mounted at its
own route (`/films/new`), not opened over another screen, but was styled like
a popup dialog (`.modal-backdrop`/`.modal`). Per the user's wireframe, turned
it into a real fullscreen page using the wireframe's exact copy, and reworked
the "Your film is being prepared" animations per follow-up feedback mid-task.

- `ImportFilmModal.tsx` → renamed `ImportFilmPage.tsx`. Dropped the modal
  chrome entirely; now a fullscreen page split down the middle with a real
  divider (mirrors `StartScreen`'s existing split-with-divider layout), title
  field pinned above the split, checkbox + Submit pinned in a footer below.
  Exact wireframe copy used verbatim: "Import new film", "We'll need…", "The
  film itself", "And your script", the script column's descriptive caption,
  and the "Run Discovery agent to detect details?" checkbox label (already
  matched). Submit button now says "Submit" (was "Start Creating", which the
  wireframe reserves for the *next* screen). Drop zones got a cloud-upload
  icon for visual weight. New CSS: `.import-page*`, `.import-columns*`,
  `.drop-zone--big` in `index.css`.
- Scope decisions (asked the user, both took the recommended/safer option):
  video-URL-paste ingestion (the wireframe's "mp4 import or .mp4 link"
  dropdown) was **not** built — would need a new backend endpoint fetching an
  arbitrary remote URL server-side, with its own SSRF-safety review. Script
  format support stays `.srt`/`.vtt` only — the wireframe's "industry
  standard" line is shown as descriptive copy, not a new parser.
- `FilmPreparingView.tsx` / `PrepAnimation.tsx`: stage transitions were driven
  directly by backend SSE events, which in test mode can fire faster than the
  animations can register. Added `frontend/src/utils/useStageDwell.ts` — a
  small queue-based controller that holds each stage on screen for a minimum
  2s before advancing to the next, draining bursts one at a time rather than
  jumping straight to the latest (`'error'` still bypasses the queue and
  shows immediately). Also added a `'preparing'` display-only stage — the
  wireframe's stage 1 ("Your film is being prepared") — shown from the moment
  the page mounts, before any real backend event has arrived, so all of the
  wireframe's stages are now visually distinct (idle → video upload → script
  upload → discovery scan → finalizing/packing → ready), not just the 4
  backend `FilmPrepStage` values that existed before. "Start Creating" now
  gates on the *displayed* stage reaching ready, not the raw one.
- Reworked the per-stage SVG animations in `index.css` for more visual
  polish: bigger scene canvas, a soft pulsing glow behind each icon, rising
  particles along the upload beam, radar-style ping rings + a brighter
  magnifier during discovery, a settle/bounce on the gift box, and a bigger
  multi-color confetti burst + pop-ring behind the checkmark on the ready
  scene. Looked at a few CodePen references for common upload/checkmark
  animation patterns as a sanity check on the approach (not copied — see
  chat for links); own SVG/keyframes throughout.

Decisions:
- No ADR needed — UI-only, no pipeline/architecture change.

Open items:

  wireframe are deliberately deferred (see scope decisions above) — worth
  their own task if wanted later.

Walked the full flow live (test mode, both themes) via the dev servers:

## 23:45 — Sitewide typography / visual hierarchy pass

User feedback: opening any screen, it's hard to tell where to look first —
headings, labels, and body text read as "relatively equal" size. Audited
`frontend/src/index.css` before touching anything: only 3 font-size tokens
existed (`--eyebrow-size` 11px, `--text-h1-size` 26px, `--text-h2-size` 17px)
against 13 other hardcoded pixel literals scattered across ~50+ selectors,
with the "important" text (list titles, dialog titles, the project's own
name) compressed into an 11–15px band barely distinguishable from body text.
Researched visual-hierarchy/typographic-scale practice online first (ratio
jumps of 1.2–1.5× between levels, dense/data-heavy UIs should *exaggerate*
jumps further, size+weight+color should reinforce each other, sub-12px text
reads as unreadable/ignorable) — see chat for the specific sources — then
wrote a plan and got it approved before touching code.

- Replaced the ad hoc token block in `index.css` `:root` with a 7-tier scale,
  renamed to match actual semantic roles (audit found only 6 real
  `<h1>`/`<h2>` tags in the whole app — everything else was a styled
  `<p>`/`<span>`, so "h1/h2" names weren't meaningful anyway):
  `--text-display` (30/700, page identity — film title, "Import new film",
  "Projects"), `--text-subhead` (24/700, an entity's own name nested inside a
  page — currently only the project name), `--text-section` (20/700, panel
  labels — was 17/600), `--text-item` (16/600, list/card row titles + dialog
  titles — was 15px at two different weights), `--text-body` (14/400,
  formalizes the existing hardcoded body size), `--text-caption` (12/500,
  absorbs the old *undocumented near-duplicate* 12px and 13px "default small
  text" sizes), and unchanged `--eyebrow-*` (11px, table/field labels).
- Project name (`ProjectPanel.tsx`, via `.project-panel__heading
  .section-heading`) moved off a one-off 19px hardcode onto the new subhead
  tier so it clearly outranks plain section labels like "Activity log"
  around it, the same way a film title outranks its own panel labels.
  `.content-card__primary` (film titles in list rows) and `.modal__title`
  (dialog titles) promoted to the item tier — previously weaker (15px/500)
  than a generic section heading despite being the most important line in
  their row/dialog.
- Removed a redundant duplicate "Details" heading in `FilmWorkspaceView.tsx`
  (~line 370) that repeated the already-selected "Details" tab's own label
  right below it — pure clutter.
- `.workspace-tabs__tab` nudged 12px → 13px (research: sub-12px is hard to
  read/easy to ignore) — stays intentionally small/dim as nav chrome, just
  off the unreadable floor.
- Swept ~30 selectors from hardcoded 12px/13px onto `--text-caption-size`
  (`.content-card__secondary`, `.checkbox-field`, `.btn`, `.results-status`,
  `.link-back`, `.import-columns__caption`, `.finding-card__text`, table
  input/select cells, etc.) — deliberately left `.chat-bubble` (actual
  message content, not meta) and the tab label (kept at 13px on purpose)
  untouched.
- Size/color pairing spot-fix: `.finding-card__rubric` and
  `.chat-panel__library-item-name` were full-bright `--text` at caption-
  adjacent sizes despite being secondary/meta content — dimmed to
  `--text-dim` so brightness consistently signals "this is the important
  line," matching how `.details-table th` was already correctly small+dim.

Decisions:
- No ADR needed — UI/CSS-only, doesn't touch pipeline architecture.
- Renamed tokens rather than keeping old h1/h2 names alongside new ones —
  only a handful of selectors referenced each, so the rename was a clean
  sed pass with no ambiguity risk.

Open items:
- None blocking. Some literal one-off text (`.menu-bar__brand-word` logo,
  `.passcode-gate__title` "Login", `.subtitle-display` on-video overlay,
  `.score-circle__value/__max`) was deliberately left outside the content
  hierarchy — branding/specialized widgets, not part of the "which screen
  element matters most" problem.

Verified: `npm run test:frontend` (60/60 passing) and `tsc --noEmit` clean —
this was CSS-only plus one JSX text removal, no logic changes. Walked
StartScreen, a film's Details/Project tabs, ProjectsLibraryView, and a modal
live via the dev servers in both themes; confirmed the project name now
visibly outranks its surrounding section labels and the film title reads as
the unambiguous top of the page.
