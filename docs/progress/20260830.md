# 2026-08-30

## Premiere-style zoomable timeline + horizontal transport bar

The user shared a Premiere Pro screenshot as a style reference and asked for the
workspace to feel more like a real NLE, specifically calling out: the timeline
scrubber being unreadable for a long (e.g. 2-hour) film with no way to zoom in, no
time ruler, no numeric time display anywhere, and the transport controls (play/
pause/etc.) sitting in a cramped vertical strip beside the video instead of a
horizontal bar underneath it like Premiere's Program Monitor. Planned this with the
user first (decisions: plain scroll-to-zoom with no modifier key, drop the
redundant "back to films" button from the new bar, fold picture-zoom into the same
bar) before implementing.

- **`frontend/src/components/VideoScrubber.tsx`** — full rewrite. Split the old
  single flat `.scrubber` div into a `.scrubber-viewport` (real `overflow-x: auto`,
  native scrollbar) containing a `.scrubber-track` whose width is `${zoom*100}%`.
  Every existing position (subtitle blocks, fill, playhead) was already expressed
  as a percentage of full duration, so it scales correctly with zoom for free —
  only the container width/scroll position needed new logic. Added:
  - A time ruler with "nice" tick spacing picked from a fixed candidate list
    (100ms…2hr) so labels never overlap regardless of zoom or clip length.
  - Scroll-wheel-to-zoom via a **native** `wheel` listener (`{ passive: false }`)
    attached in `useEffect`, since React 17+ registers `onWheel` passively at the
    root and won't reliably let `preventDefault()` stop page scroll otherwise.
    Zoom is centered on the cursor (classic zoom-to-pointer math).
  - `+`/`−`/Fit buttons next to the timeline for non-scroll access.
- **New `frontend/src/components/TransportBar.tsx`** replaces the deleted
  `VerticalToolbar.tsx`: one horizontal row (skip-back/play-pause/skip-forward,
  a `formatClock(current) / formatClock(duration)` readout, then picture-zoom
  controls) under `.video-stage` instead of beside it —
  `.workspace__panel--video` flipped from `flex-direction: row` to `column` to
  make this the actual layout, per the user's ask.
- `tsc --noEmit` clean, frontend suite 54/54, live-verified in a real browser
  (ticks, zoom-to-cursor, time readout, native panning).

## Follow-up feedback, same session

Three more requests landed while live-verifying the above:

1. **The auto-follow-playhead effect was actively fighting the zoom-to-cursor
   math** — the user zoomed into a region away from the current playhead and
   watched the view snap back to the playhead instead of staying where they'd
   zoomed. Root cause: a separate `useEffect` re-centering the viewport on
   `currentTimeMs` whenever `zoom` changed ran *after* the wheel handler's own
   cursor-centered scroll adjustment, silently overriding it. Fixed by removing
   that effect entirely, per the user's explicit "you don't have to jump to
   that."
2. **Sub-second granularity when zoomed in deep**: `formatClock()` only ever
   shows whole seconds (by design — nothing else in the app needs finer), so at
   zoom levels where the ruler's "nice step" picks a sub-second interval
   (100/250/500ms), every label was rendering as the same whole-second value.
   Added a ruler-local `formatTickLabel()` in `VideoScrubber.tsx` that appends
   `.mmm` only when `stepMs < 1000` (e.g. "00:01.250") — kept local rather than
   changing the shared `formatClock()`, since the transport bar and
   `AgentStatusPanel` deliberately don't want that precision.
3. **A second "bird's-eye" track for curated Details rows**, below the existing
   subtitle-entry track — mirroring a real NLE's multiple stacked tracks (the
   reference screenshot's V1/A1/A2/A3/A4 rows). `VideoScrubber` gained a
   `detailRows: DetailRow[]` prop and a second `.scrubber-content--details` row
   rendering one block per row (`startMs`/`endMs`, label falling back through
   `subtitleText` → `segmentDescription` → `gesture` → `notes`), accent-blue
   instead of the subtitle track's default panel styling so the two tracks read
   as visually distinct at a glance. Added a fixed-width `.scrubber-labels`
   column to the left of the scrollable viewport ("Subtitles" / "Details"),
   matching Premiere's fixed track-header column that stays put while the track
   content scrolls underneath it.
   - Also asked for the whole scrubber area to be **vertically resizable** via a
     drag handle, so a taller drag gives both tracks more room to read. Added
     `workspace__scrubber-divider` in `FilmWorkspaceView.tsx`, mirroring the
     exact same delta-based pointer-drag + `localStorage` persistence pattern
     already used by the existing left/right panel divider
     (`workspace.scrubberHeight` key, 84–400px clamp, defaults to 96px).
     `VideoScrubber`'s internal rows switched from fixed pixel heights to a flex
     column (`flex: 1 1 0` per row) so they grow/shrink proportionally with the
     container instead of clipping.
   - **Found via the fix itself, not a separate bug report**: the original
     zoom-state design read `zoom`/`viewportWidth` from the wheel handler's
     closure (re-subscribing the listener via the effect's dependency array on
     every change). Verified live that a burst of synthetic wheel events fired
     faster than React could re-render — realistic for an actual trackpad —
     only ever applied the *last* event instead of compounding, because every
     event in the burst computed from the same stale base. Fixed by moving
     `zoom`/`viewportWidth` into refs (`zoomRef`/`viewportWidthRef`) that the
     handler reads and writes synchronously, with `commitZoom()` syncing the
     ref back into React state for rendering. 20 synthetic wheel ticks with
     realistic spacing now compound correctly (100% → 1637%, matching
     `1.15^20`).
4. **"Those scrollbars look default as fuck"** — added a themed scrollbar rule
   (`scrollbar-color`/`scrollbar-width` for Firefox, `::-webkit-scrollbar*` for
   Chromium) applied globally via `*` in `index.css`, right after the base
   reset: thin, transparent track, `--border-strong`-colored thumb that lights
   up `--accent` blue on hover — replacing the native OS scrollbar chrome
   (most visible on the new timeline's horizontal scrollbar, but applies
   app-wide since a stock scrollbar anywhere would clash the same way).

- Live-verified all four fixes in a real browser (test mode): confirmed
  zooming into a region away from a mid-video playhead position no longer
  snaps back; confirmed sub-second tick labels ("00:00.100", "00:00.200", …)

  compounding fix with 20 realistically-spaced synthetic wheel events;

  Cleaned up: deleted the test film via a direct `DELETE` call, removed

## One more small tweak

The scrubber's `− 100% + Fit` zoom cluster was a horizontal row; the user asked
for it to be vertical instead — a one-line CSS change (`.scrubber-zoom`'s
`flex-direction: row` → `column` in `index.css`), no JSX changes needed since
the existing DOM order just restacks top-to-bottom. Verified via computed
style/bounding-rect in a real browser (`flexDirection: "column"`, increasing
`top` values for each button).

## Volume control

Added a mute button + slider to `TransportBar.tsx`, between the playback
controls and the time readout. `volume`/`muted` state now lives in
`FilmWorkspaceView.tsx` and is pushed onto the `<video>` element imperatively
via a `useEffect` (volume/muted aren't reactive JSX props, same pattern as
`currentTime` elsewhere in this view). Dragging the slider up while muted
auto-unmutes, matching every real media player's convention; the mute button
itself preserves the last volume rather than zeroing it. The slider itself is
custom-styled (`::-webkit-slider-thumb`/`::-moz-range-thumb`, an inline
`linear-gradient` fill tracking the current value) to match the dark theme
instead of a stock OS slider, following the same reasoning as the earlier
themed-scrollbar pass.

Live-verified: initial state (volume 1, unmuted); dragging the slider updates
`video.volume` in real time; clicking mute sets `video.muted` while preserving
the underlying volume value (slider visually drops to 0, icon → 🔇); dragging
the slider back up while muted auto-unmutes (icon → 🔊, `video.muted` false
again); the gradient fill's inline `background` matches the current value.
`tsc --noEmit` clean, frontend suite 54/54.
