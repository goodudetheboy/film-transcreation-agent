Separate fix while trying to start the dev servers: `dev:frontend`'s fixed
port 5173 was already in use locally. Nothing in the app actually depends on
that exact port (CORS is wide open — `app.use(cors())` with no origin
allowlist — and there's no OAuth redirect URI registered to it, only
Firebase email/password auth), so added `"autoPort": true` to
[.claude/launch.json](../../.claude/launch.json)'s `dev:frontend` entry
rather than hunting down and killing whatever else was holding the port.

Also, separately: user asked for a `?user=...&password=...` URL parameter
that auto-signs-in on load, intended as a quick way to hand a demo account to
a hackathon judge, with the URL scrubbed after sign-in. Declined to build it
as specified — scrubbing the URL client-side doesn't address the two real
leaks (the credential is already in the request the moment it hits the dev
server's own access log, and the "private" DM/email it's sent through
persists a plaintext copy of a real account password in that platform's own
logs regardless of app behavior). Proposed a `/demo?token=...` route instead
— a short-lived/single-use opaque token minted server-side via the Firebase
Admin SDK already used for account provisioning, exchanged for a custom
token and never exposing the real password anywhere. Not yet built — waiting
on the user to confirm which demo account it should point to.
