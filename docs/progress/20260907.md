**Part 2 — real run status on Agent Status badges.** `ChatSessionStatus`/
`DiscoveryChatSessionStatus` (`'idle'|'streaming'|'error'`) only tracks
whether a chat reply is actively streaming — it flips back to `idle` the
instant a turn's reply finishes, saying nothing about a `DiscoveryJob`/
`ResearchRun` batch pass the session kicked off, which keeps processing
in the background via `discoveryQueueWorker.ts`/`projects.ts`'s batch loop.
New [agentRunStatus.ts](../../frontend/src/utils/agentRunStatus.ts):
`collectRunRefs(turns)` pulls every jobId/runId a session's turns ever logged
via a `run` marker part, and `combinedAgentStatus(chatStatus, runStatuses)`
folds them together — aggregating over every run a session ever kicked off
(not just the latest), so one still-queued run among several keeps the row
reading "running". Wired into all three places this badge renders:
[FilmAgentsTab.tsx](../../frontend/src/components/FilmAgentsTab.tsx) (now
also fetches `listDiscoveryJobs(filmId)` and folds `listResearchRuns(p.id)`
into its existing per-project batch — no new N+1, `AgentRow.status` simplified
to hold the already-combined value, `statusModifier`/`statusLabel` deleted),
and the session-switcher lists inside
[DiscoveryChatPanel.tsx](../../frontend/src/components/DiscoveryChatPanel.tsx)
and [ResearchChatPanel.tsx](../../frontend/src/components/ResearchChatPanel.tsx)
(each fetches its own job/run status list once alongside its existing session
list fetch). No backend changes needed — `listDiscoveryJobs`/`listResearchRuns`
already existed and already return `status`.
