## 02:35 — Mention chip overflow + visibility

User flagged (with a screenshot) a reference chip overflowing horizontally
out of its chat bubble — a `@`-mention pill referencing a Detail row spilled
past the bubble and even past the panel's left edge, clipped mid-word. Root
cause in [chatReferences.ts](../../frontend/src/utils/chatReferences.ts) and
[index.css](../../frontend/src/index.css): `chipDisplayText()`'s label
truncation was capped at 40 characters, which combined with the "Detail
HH:MM–HH:MM: " prefix produces a ~65-70 char string; `.mention-chip` sets
`white-space: nowrap` with no `max-width`, so at typical chat-panel widths
(the now-resizable panel from earlier today defaults to 420px, easily
narrower in practice) that string doesn't fit and the unbreakable chip
just overflows its container. Fixed both the trigger and added a hard
safety net: `MAX_LABEL_LENGTH` 40 → 26 (short enough to fit comfortably at
common panel widths — the label is for human identification only, the model
gets full row context separately per turn, so a shorter label loses nothing
functionally), and `.mention-chip` gained `max-width: 100%` +
`text-overflow: ellipsis` so even a still-too-long chip in an unusually
narrow panel truncates cleanly instead of overflowing.

Same conversation, user separately asked to make the chip a distinguishable
blue — turned out to be a real contrast bug, not just a nice-to-have:
`.mention-chip` used `background: var(--accent-dim)`, the *exact* background
`.chat-bubble--user` itself uses, so a chip inside a user message was nearly
invisible (only its equally-dim border set it apart). Changed to solid
`var(--accent)` background with `var(--accent-on)` (white) text — reads
clearly against both the user bubble's `--accent-dim` and the model bubble's
`--panel-2`, in both themes (neither `--accent`/`--accent-on` is
theme-overridden).

No new ADR — CSS/constant tuning within the existing mention-chip design
(the drag-and-drop chip system from earlier this week). Verified:
`npx tsc -p tsconfig.app.json --noEmit`, `oxlint`, and `npx vitest run`
(chatReferences.test.ts's truncation test only asserts "contains an ellipsis,

servers: sent a message embedding a long detail-reference token directly
through the (mock) messages API, confirmed the redisplayed chip truncates
