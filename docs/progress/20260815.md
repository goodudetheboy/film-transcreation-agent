## 20:24 — Rename proxy → backend, add one-click dev script

- **Found and fixed a real bug in `dev.sh` by testing it, not just writing it**: on
  Windows, `npm run dev:X &` spawns a process *tree* (npm → npm -w X → tsx/vite);
  killing only the top PID or the port-bound leaf process leaves middle wrapper
  processes orphaned. Fixed with `taskkill //F //T //PID` (Windows tree-kill) as the
  primary cleanup, kept PID/port-based killing only as a last-resort fallback.
  Verified by starting the script, tree-killing the same way `kill_tree` does, and
  confirming zero leftover processes and both ports free.

## 21:40 — Fix passcode UX + dotenv bug, film-editor redesign

- **Real production bug**: `dotenv` was a listed dependency but never actually
  imported anywhere — `backend/.env` was silently ignored at runtime, so
  `SHARED_PASSCODE` always fell back to its hardcoded default. Root-caused by
  testing live in a browser and comparing curl output against the `.env` file on
  disk. Fixed with one line: `import 'dotenv/config'` in `backend/src/server.ts`.
  None of the unit/integration tests caught it because they all inject config
  directly into `createApp()`, bypassing `loadConfig()`'s env-reading path.
- **Real UX bug**: `PasscodeGate` accepted any non-empty string and only found out
  it was wrong after a full script submission. Added `POST /api/verify-passcode`
  (guarded by the same `passcodeMiddleware`), called by the gate itself before ever
  showing the main UI, with an inline error on mismatch.
- Added `ErrorBanner` — sticky, full-width red bar at the top showing the exact
  error (status code + backend detail) with a "Try again" button, per user request
  for easier debugging. Refactored `apiClient.ts`'s error-detail extraction into a
  shared `describeError()` helper.
- Since passcode is now verified before reaching the main form, "Try again" just
  resets the results store and stays on the form instead of bouncing to the gate.
- Full visual redesign ("film editor," sharp corners): dark single-theme CSS system
  (near-black background, amber accent, monospace, `border-radius: 0` everywhere),
  two-panel "editing bay" layout.
- Verified live in a real browser end-to-end; caught and fixed one bug live
  (password input hadn't picked up the dark styling — CSS selector only covered
  `type="text"`).
