## 00:25 — Research agent "sources" showing bare numbers instead of URLs

User screenshotted a scored rubric's Evidence section showing "4", "11",
"14" as the source links instead of real URLs — traced to
[researchAgent.ts](../../backend/src/services/researchAgent.ts). The batch
call runs Gemini with the `parallelAiSearch` grounding tool, but the prompt
only asked the model to self-report `"sources": ["<url>"]` inside JSON it
composes by hand from `response.text`; the code never read
`response.candidates[0].groundingMetadata`, where the actual searched URLs
live (`groundingChunks[].web.uri`). The model, following the grounded-answer
footnote convention it's trained on, sometimes wrote the citation index
number instead of the URL it can't easily transcribe into hand-written JSON.
`frontend/src/components/ProjectItemView.tsx`'s source list just does
`<a href={src}>{src}</a>`, so a numeric "source" renders as blue link-styled
text pointing nowhere.

Fix, two layers: tightened the prompt's OUTPUT section to require a full
`http(s)://` URL in every `sources` entry and explicitly forbid a bare
citation number, with an instruction to leave the array empty instead of
guessing; and added `resolveSources()` as a safety net — after parsing the
JSON, it pulls the real URLs out of
`response.candidates?.[0]?.groundingMetadata?.groundingChunks`, and for any
source string that isn't already a URL, tries to resolve it as a citation
index into that array (both as given and off-by-one, since the model's own
indexing isn't guaranteed) before falling back to dropping it. Widened
`GenAIClient`'s return type to expose `candidates`/`groundingMetadata` so
this could be typed and tested without touching the real Vertex SDK.

Caveat flagged to the user: this only fixes future research runs. Scores
already persisted in Firestore (`projects/{projectId}/items/{itemId}`, via
`projectItemStore.ts`) with numeric "sources" values stay broken until that
item is re-researched or a human manually re-edits the rubric's sources
through "Edit score" in the UI — not yet checked how many existing
items/scores in the live project have this pattern.

No new ADR — behavior fix within the existing research-agent design, not an
architectural change. New tests in
[researchAgent.test.ts](../../backend/src/services/researchAgent.test.ts):
one confirms a bare `"4"` resolves to the matching grounding chunk's URL,
one confirms a citation number with no matching chunk gets dropped rather
than persisted. Verified: `npx tsc -p tsconfig.json --noEmit` clean (backend),
full `npm run test:backend` 301/301 passing (2 new). Not
live-walked via the dev servers — this is backend-only, and reproducing the
original bug needs a real Gemini+Parallel grounding call this session
doesn't have credentials/quota to drive live.

Shipped straight to `main` per explicit user direction.
