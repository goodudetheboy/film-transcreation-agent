# 2026-09-06

## 00:20 — Phase 4 implemented and verified

Planned (via a written plan approved before coding) and implemented both Phase 4
"Run/Details UI overhaul" backlog items.

**1. Discover run: count badge → modal, with bulk actions.** User decided bulk
add/discard needed new backend endpoints (one round trip regardless of selection
size), not a client-side loop over the existing per-row endpoints.
[discoveryResultActions.ts](../../backend/src/services/discoveryResultActions.ts)
gained `mergeDiscoveryResults`/`discardDiscoveryResults` (plural) alongside the
existing singular ones (unchanged — still used by the chat agent's
`merge_candidate_row`/`discard_candidate_row` tools): one `getJob`, one bulk
`DetailRowsStore.addRows` (new method, `firestore.batch()` in the Firestore impl —
exact precedent: `projectItemStore.ts`'s `createItems`), one `updateJob`. Two new
routes in [films.ts](../../backend/src/routes/films.ts) —
`POST .../discovery-jobs/:jobId/results/bulk-add` and `.../bulk-discard`, both
taking `{ tempIds: string[] }` (POST, not DELETE, for discard — a DELETE with an
array body isn't this codebase's style). Frontend: new
`bulkMergeDiscoveryResults`/`bulkDiscardDiscoveryResults` in
[filmsApiClient.ts](../../frontend/src/api/filmsApiClient.ts).

In [DiscoveryChatPanel.tsx](../../frontend/src/components/DiscoveryChatPanel.tsx),
a done run's candidate list collapsed to a `run-result-badge` pill ("N details
found") that opens a new `DiscoveryResultsModal` — a checkbox table (leftmost
select-all-then-act column, per-row Add/Discard kept for a quick single action) with
a top "Add N selected"/"Discard N selected" action bar. Selection is pruned
whenever the underlying job's `resultRows` shrinks (via a `useEffect`), so a stale
tempId can't ride along into a later bulk call. Deliberately doesn't auto-close when
candidates run out — shows "All candidates handled." and waits for the user, so an
in-flight action never yanks the dialog away under them.

**2. Details table row click → in-panel, not modal.** Mirrors
`ProjectPanel.tsx`/`ProjectItemView.tsx` exactly. New
[DetailRowView.tsx](../../frontend/src/components/DetailRowView.tsx) — same
back/prev/next/dropdown header shape as `ProjectItemView.tsx`, minus a chat-toggle
button (Discovery chat is film-scoped, not row-scoped; its toggle already lives one
level up in `FilmWorkspaceView.tsx`'s toolbar, untouched by this change). All the
editing logic (`draft` state, start/end commit, "use current playhead", save,
delete) moved out of [DetailsTable.tsx](../../frontend/src/components/DetailsTable.tsx)
into `DetailRowView.tsx`, seeded from its `row` prop instead of a separately-managed
draft keyed by an `editingRowId`. `DetailsTable` now keeps a plain `openRowId` and,
when set, returns `<DetailRowView>` instead of the table — same full-content-swap
pattern as `ProjectPanel`'s `if (openItem) return <ProjectItemView />`. No changes
needed in `FilmWorkspaceView.tsx` — the swap is fully internal, same as `ProjectPanel`
today. `provenanceLabel`/`provenanceModifier` (needed by both the table's Source
column and the row view's Source field) moved to a new
[detailRowProvenance.ts](../../frontend/src/utils/detailRowProvenance.ts) util
rather than staying component-local, which also cleared an oxlint
only-export-components warning that appeared once `DetailsTable.tsx` exported them
for reuse. Deleted the now-dead `.detail-row-modal`/`.details-table__row--editing`
CSS (the table never renders while a row is open, so neither rule can match
anymore); `.detail-row-modal__readonly` renamed to `.detail-row-view__readonly`.

Decisions:
- No new ADR — both items are additive UI/route changes; the bulk endpoints follow
  an existing precedent (`projectItemStore.ts`'s `createItems`) rather than
  introducing a new pattern.
- Kept the per-row Add/Discard buttons inside `DiscoveryResultsModal` alongside the
  new bulk bar, rather than removing them — a quick single-candidate action
  shouldn't require selecting it first.
