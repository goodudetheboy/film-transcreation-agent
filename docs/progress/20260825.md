## 09:15 — Research agent redesign: exhaustive per-rubric scoring, verdict, suggested replacement

- User asked for a real behavior change: instead of Research selectively deciding which rubrics
  apply and gathering findings for those, every detail should be scored 0-10 against **every**
  rubric (exhaustive, no skipping), with a synthesized per-item verdict ("should this be
  transcreated, and why") and, when yes, one suggested replacement + justification. This directly
  contradicts `docs/adr/0012`'s explicit "evidence-gathering only, no ranking or fix" scope
  decision — not a silent drift, since 0012's Status is now `Superseded by 0014`, and
  `docs/adr/0014-research-agent-exhaustive-scoring-and-verdict.md` records the new decision, why,
  and the open consequences (Prioritization's/Proposal's future scope are both narrower now).
- Ran this as a full Plan-Mode cycle before touching code: an Explore agent mapped every current
  consumer of the old `RubricFinding`/`ResearchResult` shape (10 files, with exact line
  references), three clarifying questions confirmed score semantics (relevance/match-strength to
  the rubric's concern, not a "fit" score — higher = stronger risk signal) and the
  exhaustive-scoring-but-lazy-web-search tradeoff, then a Plan agent produced the detailed
  file-by-file design, which I verified against the two most detail-sensitive files myself
  (`researchAgent.ts`'s prompt/test string-slice dependency, `ProjectDetailView.tsx`'s exact JSX)
  before writing the final plan and getting it approved.
- Implemented in the planned order: `researchAgent.ts` (new `RubricScore`/`SuggestedReplacement`
  types, rewritten prompt, new snake_case→camelCase mapping) → its tests → `mockResearchAgent.ts`
  (now actually consumes the `rubrics` param it previously ignored, still surfaces the same real
  documented Inside Out/Japan broccoli case) → its tests → `projects.ts` (`totalFindings` →
  `totalRecommendedForChange`) → its route tests → the integration test fixture → frontend
  `apiClient.types.ts` → `ProjectDetailView.tsx` (new verdict block, suggested-replacement block,
  per-rubric score list with color-tiered scores, a compact verdict badge next to the existing
  pending/done status badge) → its CSS → its test.
- **Caught a real React bug while implementing, not just a schema mismatch**: my first draft placed
  a new `useMemo` (for a rubric-id → description lookup) *after* the component's existing
  conditional early returns (`if (!currentProject) return ...`), which violates the Rules of Hooks
  — hooks must run unconditionally, same order every render. Fixed by moving the `useMemo` above
  both early returns, with a `currentProject?.rubrics ?? []` guard inside it instead.
- Final sanity check: grepped the whole repo for `RubricFinding`, `.findings`, `reasonToChange`,
  `changeDirection`, `totalFindings` — zero hits, confirming nothing was missed.
